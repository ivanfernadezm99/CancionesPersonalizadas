# Proposal: Suno Tag Validation (artist names in reference_song)

## Intent

Suno rejects generation (code=400) when `reference_song` contains an artist name — it is injected verbatim into the `prompt`/`style` tags as " Inspirada en el estilo de {reference_song}.". Result: failed jobs, raw English Suno errors, users forced to redo the preview flow. No content validation exists on any field flowing to Suno; `reference_song` is the primary vector (reported bug: "los palmeras").

## Scope

### In Scope
- Shared sanitizer: strip `"Song - Artist"`, `"Song de Artist"`, `"Song (Artist)"` → keep song token, plus a small curated blocklist (popular Argentine artists)
- Input-time validation on `reference_song` (create + patch) → 422 with a friendly Spanish message when only an artist remains
- Generation-time guard so legacy projects stored before the fix are covered
- Error translation: Suno artist-rejection message → friendly Spanish in the job `error` field
- Frontend: fix hint text that teaches the rejected format; surface the translated error
- Update test fixtures/docstrings that promote the `"Song - Artist"` format

### Out of Scope
- Full artist database or external moderation API
- Sanitizing `recipient`, `idea`, `story` (LLM-echo risk — lower, deferred)
- Changing `reference_description` (auto-generated by audio analysis)
- Committed `SUNO_API_KEY` in `.env.docker` (secret leak — separate change)

## Capabilities

### New Capabilities
- `tag-sanitization`: shared strip heuristic + curated blocklist used by input validation, the generation-time guard, and mirrored client-side.

### Modified Capabilities
- `song-projects`: `reference_song` validated/sanitized on create + patch (RQ-PRJ-01/02, RQ-REF-01)
- `voice-configuration`: `build_prompt` sanitizes before appending style reference (RQ-VOI-05; scenario updates)
- `lyrics-generation`: sanitized reference flows into the LLM prompt (RQ-LYR-04/06; scenario updates)
- `suno-provider`: artist-rejection error translated to friendly Spanish (RQ-SUNO-01)
- `job-orchestration`: translated error in status; consistent `reference_song` handling across `project_worker`/`job_worker` (RQ-JOB-02/06, RQ-RS-*)

## Approach

One shared sanitizer module, applied at three layers: input (Pydantic 422), generation (`build_prompt` + lyrics prompt builder — covers legacy projects and both worker paths), and error translation in the job-failure path as a safety net for anything local heuristics miss (Suno's matching is opaque). Frontend mirrors the strip and fixes the hint.

## Risks

| Risk | Likelihood | Mitigation |
|------|------------|------------|
| Heuristic misses (band name typed alone) | Med | Curated blocklist + error-translation net |
| Silent user-input alteration | Med | Strip only `- Artist` patterns; reject pure-artist with 422, never silently drop |
| Existing fixtures/docstrings embed the rejected format | High | Explicit task to update tests + examples |
| Worker paths drift again | Med | Centralize sanitize in the shared module |

## Rollback Plan

Remove sanitizer call sites (validator, `build_prompt`, lyrics builder); keep error translation if it is isolated and safe. No data migration — stored `reference_song` values are untouched; the guard is read-time only.

## Dependencies

None external. Suno's artist matching remains opaque by design.

## Success Criteria

- [ ] `"Bachata Rosa - Juan Luis Guerra"` accepted as `"Bachata Rosa"`; `"Los Palmeras"` → 422 on input, sanitized/friendly error on legacy jobs
- [ ] No raw English Suno artist-rejection message reaches the frontend
- [ ] Frontend hint no longer shows artist-format examples
- [ ] A legacy project already stored with an artist name generates without code=400
